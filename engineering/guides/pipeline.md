# 从母版到可交付形象

## 决策顺序

1. 判断请求是新角色、局部修补、动作调整还是交付。已有形象只改相关部件；不要先生成整套新身体。
2. 锁定完整母版、画布、方向、文件哈希、保留项和允许改变项。新角色填 `templates/asset-contract.json`；龙娘读取 `current-project.json`。
3. 在完整角色上设计目标姿态，确认肩线、腰胯、近远腿、短臂和裙摆关系。坐姿改稿失败说明：先孤立生成身体，容易与头部的三分之四朝向冲突。
4. 原位提取可见部件；只有运动后将露出的区域才补画。记录被遮挡对象，不把整张无翼完整图当作后发。
5. 用明确未编辑区域配准，保留单一等比变换、遮罩和来源。生成图自身 alpha 决定新轮廓；不能套用旧坐姿/旧翼剪影。
6. 先合成无动画全身，再试最大动作。相同问题连续两次未改善，就重新定位来源/遮罩/变换，不继续扩补片。
7. 接入官方 kit 与本角色适配器。分层只增加确有独立运动或遮挡需要的组件；连续刘海不必为了“层数更多”强拆。
8. 按 [检查与交付](validation-and-release.md) 分别完成机器检查、视觉证据和宿主验证，最后打包。

## 三条工作路线

**已有形象调动作：** 在 `model.json` 和对应 JS 中找生效参数 → 单个动作小样 → 进入/退出和组合状态 → 采样。无需重画贴图。

**局部素材编辑：** 当前完整角色作风格参考 + 问题区裁图 → imagegen 定点编辑 → 配准/自己的 alpha → 最小语义区接入 → 全身复核。提示词使用 `templates/image-edit-prompt.md`，保存逐字文本、输入和原始输出。

**全新形象：** 新角色自己的母版/坐标/部件契约 → 头、肩袖、眼部四个小样 → 基础状态 → 扩展姿态和表情 → 目标机器验收。可以学习代码结构和官方节奏，不直接继承龙娘的头脸坐标。

## 先复制实验包

```sh
python engineering/tools/project.py candidate --id my-test --name 测试形象 --author 作者名
```

结果在 `scratch/candidates/my-test`。它是龙娘运行结构的实验副本，仍带原素材和来源，不能当作新原创角色。通过 `preview/engineering.html?pack=scratch/candidates/my-test` 检查。此命令不会安装、覆盖生产包或删除旧形象。

## 最少而充分的交接材料

- 完整母版及 hash，当前 pack，显式素材/配准契约。
- 每次图像编辑的输入、逐字提示词、原始输出、区域/变换。
- 完整角色证据和缺陷区放大；不要只交诊断分件图。
- 变更报告：原因、方案、影响动作、通过项、未测试项、旧方案是否失效。

原位重组一致只适用于原位像素提取阶段。后来明确重绘了坐姿、衣裙或尾巴，不能继续沿用旧 `rest_pixel_mismatches=0` 当作当前全身一致结论。
