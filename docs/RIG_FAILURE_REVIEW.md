# 分件绑定失败复盘（2026-10-13）

结论：当前动画试验失败，不能交付。用户截图里的失真来自制作方法和未执行的视觉验收，不是配色问题，也没有证据说明官方 kit 本身有缺陷。

## 已确认的原因

1. `scripts/build_dragon.py` 从独立生成的 atlas 裁出部件，再用手填的 `placements` 分别缩放。它没有保存从母版提取的原位坐标，也没有配准记录。`rig-assembly-no-face.png` 已出现头身比例变化、双重肩部轮廓和服饰接缝；动画前就不合格。
2. 身体几何被替换，`model.feat` 和 `model.units` 却从鲸鱼娘直接继承。`figure.js` 的 `FACE`、`HEAD`、眼睑曲线、眉毛位置和嘴部偏移也属于上游原画。更改关节坐标不能使这些数据自动适配新脸。
3. 虹膜按 HSV 阈值提取，遗漏浅色虹膜、高光区域。`feat/eyeL_ball.png` 可见残留紫色虹膜和完整睫毛；随后又叠加独立虹膜、睫毛，并用另一张脸的曲线裁切。这解释了重复轮廓、空洞与闭眼变形。
4. 直接复制了 37 项词表，尚未逐项视觉检查。原预览的有限数值检查也不能证明美术正确；`JSON.stringify(...).indexOf('null')` 不是有效的有限数值验证。

## 已采取的修正

- 默认预览只显示 v005 完整原画，明确标注静态候选，关闭错误动画入口。
- 失败预览、分件和代码保留为排查证据；不把现有 ORA 或运行包当成完成品。
- 旧构建脚本立即退出，防止继续批量生成同样的问题。
- 本次不重新生成整套素材，不用更多动作掩盖基础拼合缺陷。

## 重新制作的顺序

1. 以完整原画为共同坐标基准。v005 是当前候选，不代表用户已验收。
2. 从同一母版提取可见区域；只对遮挡区域局部补画。每层保留原尺寸、原位置和遮罩，禁止为适应旧骨架逐件拉伸。
3. 先原位合成无动画图，与母版叠图检查。脸、肩、衣摆、尾根不一致就留在拆件阶段。
4. 最初保留完整五官，先验证头身不变形。需要独立视线时，再拆眼白、虹膜、睫毛，检查残留并依据本角色重新建立眼睑曲线。
5. 复用官方行为系统；角色关节、变形范围和幅度必须重新适配。先验证中立、眨眼、微转头、抬臂四个小样，再扩展全动作。
6. 原尺寸、小桌宠尺寸、深浅背景、动作极值均需看图。逐个动作通过后才加入发布词表；浏览器运行不等于桌面客户端验收。
