# 黑金魔女的制作与复现手册

这套工程从透明站姿母版和已录取的生图供体开始，在同一张画布上补画、拆件、装配，再由 Coopanion API 2 驱动。按仓库首页命令可以从供体重建当前形象。重新生图仅用于改稿或制作新角色，复现当前版本应使用归档图片。ImageGen 的重复调用会有随机差异。

跨角色的动作与美术判断见[桌宠工程通用手册](桌宠工程通用手册.md)，包括星云 v2 拎起弹性、低位齐掌与倾听歪头、星眠独立坐姿和鲸鱼娘摆尾。

画布为 **1163 × 1352 RGBA**，左上为原点，x 向右，y 向下。左右按镜像后的画面方向。画面左眼为近侧浅紫眼，右眼为远侧蜜金眼。发色、黑金披肩、象牙白蝴蝶结、帽坠、腕饰、袜鞋和 Q 版比例应在两眼闭合、走跑和被拎起时仍可辨识。坐姿使用单独小凳画稿，脚和裙摆参照坐姿的空间关系。

画稿所用参考坐标、活动枢轴、轮廓接缝需要分别记录。眉弓与眼角适合用来核对五官落点，头转动用颈点，手套和鞋尖适合核对局部注册，肩髋转轴在衣物下。现行数值从 `pack/star-witch/model.json` 读取。

## 2. 从拆件到可活动部件

1. 在母版上写出前后关系，再划保护区、补绘区和接缝区。保护区包括已通过验收的手指、腕饰、金边、鞋和五官。补绘区包括袖根、裙下腿根、头发里的额头及帽檐内侧。接缝区控制在足以修复旧杂色与重复描边的范围。
2. 精确拆出可见部分供生图定位，保存残片。让模型补全被遮挡的结构。活动件完整以后，还要单独补画拿走该件后露出的后层。例如抬臂时既需要连续上袖，也需要足够长的披肩里衬。
3. 从生成图取可用的补画，应用相似变换或局部仿射配准。鞋、手套或装饰已有正确比例时，以母版的原像素为保护区，局部变换给补绘供体使用。轮廓、阴影和笔触都要接得上。全部新像素拼入同一原坐标画布，保存透明 PNG。
4. 去掉半透明边混入的旧底色。重采样供体 RGBA 时使用预乘 alpha，处理后除回 alpha；检查全透明像素、半透明边和可见主体。发现两套边，先关闭其他层，到独立素材里找残影。只有合成出现边时，再检查遮挡、预乘或相邻贴片的 alpha。
5. 按原坐标叠回母版，放大看轮廓、位置和颜色。在浅底、深底和桌宠正常大小分别检查。再做动作起点、峰值、过渡、恢复和两个朝向的截图。单张静态对齐只覆盖原位。

### 分件顺序和遮挡

| --- | --- | --- |

| 双腿与衣裙 | 拆画面左右腿，保留鞋和褶边袜，供体补上裙下连接。披肩、扣、金链、披风和裙摆归身体画稿 | 次序是后裙内衬、腿、前裙和披肩。内衬与衣身同一变换，只拆出绘制前后关系 |

| 坐姿 / 睡姿 | 从独立坐姿供体配准小凳、下垂双脚和头部。睡姿用同坐姿坐标再注册已匹配闭眼画稿 | 坐睡切换使用完整坐姿，站姿腿不参与，不播放腿部坐下动画 |

## 3. 画表情前先判断脸的空间关系

异色眼尺寸、眼角位置和前发遮住眼睛的范围来自同一张朝右母版。先拿出左右眼和遮挡关系的明确参考图，要求模型重画完整表情。近眼的睫毛与远眼经过刘海的位置各自匹配。和母版比时对齐帽檐、静态刘海、下颌这些稳定部位，再检查虹膜颜色、脸颊、嘴和眼角。

眼睛紧贴脸侧时，旧做法用眼周一圈肤色补片容易盖住前发、越过脸轮廓或在脸颊留下方形边。当前采用**一张完整表情画稿**，让皮肤、睫毛、发边及脸侧在同一张图里。绘制时保留共同的头部 alpha，整脸裁幅的外边在厚发区自然接回。遇到眼睛压穿刘海，回看原位层序和对应画稿的发边。遇到下巴突变，先量脸轮廓与头层坐标，再看哪个图层改了 alpha。两种问题都要对准原母版逐像素位置。

### 统一默认脸的肤色

表情画稿确认后，默认脸使用它们建立的共同肤色，而不是继续以偏淡的默认脸覆盖其他表情。先从对齐画稿的两侧脸颊取固定区域，筛出真正肤色像素，排除虹膜、线稿、发边及嘴。对各表情取样的中位数再取中位数，得到本项目目标色。脚本回到默认脸已有的皮肤像素作小量 RGB 修正，并以同一色标处理匹配后的表情、半闭闭眼和独立坐睡画稿。强度按颜色渐变，保留腮红、明暗和暗边。整张原始母版不改写。当前记录的默认脸样本由 `[251,227,223]` 到 `[252,222,218]`。

验收需要同时看差值和实际切换。脚本对照同一坐标的肤色取样，生气旧缝线比对同一已配准画稿，两者是不同检查。再播放睁眼、眨眼、变表情和回待机，观察有没有色闪、嘴下暗边、发色偏移或被放大的颊侧边缘。

### 眨眼和说话

- 从同一表情母版保存开、半闭、全闭三张对位画稿。每只眼分别标上下眼睑走向，中间格只采一张连续画稿进行局部变形，防止同时叠两套睫毛。全眨和远眼单眨各 17 格。单眨的接合放在中央厚刘海下。
- 说话取单独生成且对位的开口画稿。关嘴是原表情嘴，三个开口格只形变提取后的嘴部笔触。改变开口前先在每个已完成表情上修掉旧嘴笔触，保留整张表情皮肤连续。嘴部之外的像素必须一致。曾出现半开格采到下巴暗线的问题，以口型格与静态脸逐像素比较定位。
- 开心、生气、惊讶、害羞、难过、疑惑、犯困、被拎起各有对位画稿，喜欢沿用开心并叠小爱心。哭泪、心形和眩晕星由宿主或其效果形状绘制。眩晕另有对位表情与旋转的圈圈眼。

## 4. 走路、跑步、倾听与轻动作

宿主 kit 推进横向移动、转向、跳跃、抓放及状态，角色脚本计算像素画的关节变换。避免通过修改全局时间或宿主位移来调腿脚。走路按实际每帧移动量和母版单位推进步相，一个周期约 120 个母版像素，上限 1.75 周期/秒，双腿相差半周期。每条腿约 60% 为承重，40% 作抬脚回摆，按鞋底实际几何作地面补偿。配小幅上下起伏和反相摆臂，启动加速，结束短时回收。核对同一时刻有鞋底承重、接触脚没有明显滑行、启动与到达站姿连续。跑步保留较快步频和低收臂。

0.1.1 修正摆臂相位。臂的顺序是左、右，腿的绘制顺序是右、左。近臂随远腿、远臂随近腿，同侧手脚反相。预览脚本截取实际绘制矩阵，在两个朝向采集四肢明显分开的帧，要求两个步相都出现且对侧同向。使用 0.1.0 重放会在该断言失败。

倾听由宿主进入 `listening`，站姿倾角平滑交给颈轴，当前预览测得约 −6.44°。倾听期间整体舞台层与躯干保持水平，已分出的帽、脸和前发跟转，后发轻跟。独立坐姿画稿保持原坐姿。听完检查回正，拎起依然走宿主原来的悬拎和放下事件。鞠躬按站姿小幅前屈，双鞋留在地面。动作标线或锚点只出现在预览。[动作验收记录](../review/preview-qa.json)

### 拎起晃动

按[星云 v2 0.1.9 发布实现](cases/xingyun-v2/figure.js)移植。宿主的倾斜从悬拎逐步接入，进空中与落地状态时保留余摆；在抓取点抵消宿主拉伸。头用 `(70,10,16)`，发束用 `(55,7,1.8)`，两肩用 `(60,9,125)` 与 `(60,9,95)` 的同款阻尼弹簧。魔女手心在母版约 `(470,973)` 和 `(774,964)`，绕各自肩点将掌心反解到同一低位高度。腿在髋点摆动，发束用自身发根的局部旋转接收从颈部延迟来的惯性。

浏览器用宿主指针事件向两边快速拖，再停住悬空。量绘制矩阵的整体回摆、颈与躯干的相对角度、发束滞后和两掌高度，最后检查松手、落地和回待机。抓放事件与晃动质量各有检查。

### 眩晕

星眠 2.0.4 的眩晕由官方 kit 切入独立坐姿，前 2.4 秒摇头并旋转圈眼和三颗星，末段闭眼快速回正。魔女复用这组宿主时序和同款头部弹簧。宿主倾角送进颈部。坐姿画稿用官方网格做局部变形，帽与脸随颈摆，下方过渡区域把权重逐渐降到零，凳子和双腿保持原位。回正仍走同一网格和闭眼画稿。

眩晕脸采用[内置 ImageGen 的完整补画](../work/face-repair/mood-dizzy.png)，按原母版和坐姿分别配准。用周围眼白恢复圈眼下的底色，将已画好的浅紫和暖金螺旋提成可旋转的笔触。笔触各自留在眼裂内，对远侧的缩放进一步保留透视，前发和睫毛边缘沿用配准画稿。工具见 `dizzy_art.py` 与[实际提示词](../work/face-repair/眩晕补画提示词.md)。

圈眼与星星和第一帧独立坐姿同时绘制。宿主进入眩晕但站姿还在屏幕上的过渡帧保留原脸。浏览器按帧检查起始顺序，再采样坐姿网格的上端与脚底、两眼旋转、三星移位、末段闭眼和回待机。

### 裙底深度和正脸视差

最下层后裙在腿后，上方白褶边仍盖着腿根。保持可编辑的整件 `body.png`。根据原画褶线用 `skirtDepth` 只标出后侧布片，加载时分前后绘制。重组 alpha 后再叠回原位。两髋 ±10° 对照用于检查小腿露出而前裙边保持完整。[裙底与小腿对照](../review/skirt-leg-depth.jpg)

脸部在原有的整头视角变换里另用局部网格。眼口分别随 yaw 和 pitch 小幅位移，近眼变化略大。只处理已配准的当前表情，前发 alpha 邻近区域衰减移动，下颌和画幅外缘权重为零，两侧极值都要看。

一轮图像编辑只指定一个可验收的缺口和可动部件。提示词写清哪张图是编辑对象、哪张只提供位置与风格，给出保护位置、遮挡方向、预计露出范围、目标动作和完整 alpha。保留原生输出及逐轮提示。输出尺寸、位置和风格要实际比对。生图返回整张新图时，只取合格的新增部分；程序负责定位、边缘接续和验证。

示例提示词结构如下，可按本仓库的实际模板调整。

```text
Image 1 is the edit target. Image 2 is reference for placement, proportions, and brushwork.
Complete [hidden part] behind [occluder]. Leave enough overlap through [specific motion].
Protect [existing cuff, eyes, silhouette, or other anchors]. Repair only the join at [location].
Match the approved palette and line weight. Return a clean transparent RGBA image without guides.
```

## 6. 交付前的验收和回退

1. 原位检查母版方向、画布、空白 alpha、各类锚点、领口与衣边、鞋底和异色瞳。重复检查左右手的大小、方向和肩根。对未经批准的重画比例、色相或构图退回最近通过的画稿。
2. 把所有会露出隐藏结构的运动跑一轮，截初始、两极、快速切换及返回待机。重点看手臂是否穿披肩、裙摆是否放出腿根、前发是否断根、以及坐下时是否误画站姿腿。手修后直接用热更新复看，再让包中裁图与编辑层逐像素对照。
3. 运行 `review_portraits.py` 检查图集宽高、帧数、公共 alpha、缝线和颜色变化。运行 `qa_preview.mjs` 驱动浏览器验证并截图，确认走路、跑步、坐、睡、双眨、单眨、表情、说话、拎起到放下、鞠躬和倾听均实际经过各自路径。
4. `package_project.py` 验证版本清单、资源引用、原位贴图和 ZIP。将安装 ZIP 解开查看清单与所引用的贴图，再从工程 ZIP 解压到空路径、重建并比对生成的安装包。记录所在操作系统与依赖版本；不同原生 PNG 库可能得到不同压缩字节，如有差异再比对图像 RGBA 和模型数据。
5. 正式客户端用「装扮 → 导入」选安装 ZIP。核对当前加载形象、真实拎放与瞳色、切换动作、装扮缩略图，再在桌面实际尺度确认。浏览器、目标客户端和用户视觉验收分别标注。当前交接提供工程、安装包和本地验证记录，客户端导入由实际验收结果更新。
6. 大范围动手前先存当前版本及包含已验收人工修改的 `parts/`。新供体放工作区，验收后才生成发行包。若修缝后出现新的色差、错位或断口，先从对照与具体输出定位，然后只重做出问题的部位，不覆盖已通过的其他画稿。
