# 从一张母版到可修改桌宠：实做工作流

本记录来自 GPT 龙娘 v005 的制作和返工。目标是 Coopanion API 2 形象包；不是 ChatGPT Pets，也不是可直接导入 Cubism 的 Live2D 模型。官方方法、我们的实现、视觉通过和用户验收是不同层次。

## 先运行，再学习修改

```powershell
git clone https://github.com/scarlet20252025-cloud/Coopanion-Skin-Design.git
cd Coopanion-Skin-Design
npm run preview
```

浏览器打开 `http://127.0.0.1:4319/preview/dragon-r06.html`。预览只需 Node，不需配置图像 API、安装训练环境或重新生成图片。直接打包只需标准 Python，无需安装图像依赖：

```powershell
npm run check
python scripts/package-pet.py gpt-dragon-v005-r06
```

`dist` 会生成 ZIP 与 `.zip.sha256`。ZIP 根目录为 figure.json。安装和验证见 [安装与交付说明](INSTALL_AND_VERIFY.md)。不要为了预览或打包去运行素材生成脚本。

只有修改/检查美术素材时，再建独立环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-art.txt
.\.venv\Scripts\python scripts/doctor.py
```

开发包通过浏览器测试不等于通过完整桌面窗口验收。各版本状态见角色 brief.json 与对应 QA 报告。

## 一次锁定的四件事

1. 选一张透明背景母版，记录文件 SHA-256、画布尺寸与版本。构建前检查哈希。
2. 所有部件保留原画坐标。若裁边，保存 offset；不要各自居中、独立缩放再拼。
3. 定义脚底、肩、髋、头部锚点。数字属于该角色，不能直接复制本仓库的 1254px 龙娘坐标给另一角色。
4. 给近远侧或屏幕左右起明确名称。屏幕左不等于角色解剖学左。

本项目的权威入口是 `production-lock.json`。旧 atlas 和废弃母版不参与新构建；保留旧产物只为复盘。

## 局部拆件，而非重新画一遍

先从母版提取原位可见部件；仅当它移动会露出遮挡区时，再请求局部补画。例如删除袖子，补出后面的衣服/头发。编辑目标仍是母版，不以连续漂移的生成图作为下一代母版。

补画完成后：

1. 在未编辑区域做平移配准；保存变换矩阵与相关系数。相关系数仅是配准指标，不代表美术通过。
2. 用显式遮罩取所需补画区域，其余像素丢弃。AI 输出画布边缘可能有微弱噪点，不能整张作为新层接入。
3. 保存生成原图、实际提示词、遮罩、部件 PNG、可编辑 ORA、构建脚本与验证 JSON。
4. 无动作时重组，检查是否与母版像素一致。此项通过仍要看最大动作时接缝是否露底。

例子：r04 原位拆双臂，r06 仅将新掌心区域贴回原袖子，手部遮罩之外修改像素必须为 0。

## 动作差分有明确生命周期

反面手掌不能由原手臂旋转代替。制作独立掌心朝外手臂，肩与袖子几何保持原位；抬手阶段切换为差分，落手阶段切回中立手臂。不要永久覆盖待机素材，也不要随意水平翻转整条袖子导致肩点错位。

眼睛优先使用原位半闭/闭眼差分；单眼眨眼可复用已验证的一侧闭眼区。坐姿需要自己的裙腿差分。切换前后检查头部与脚底高度，避免全身跳位置。

## 绑定：复用状态，自己定义几何

Coopanion kit 管移动、重力、转身、拖拽和状态机；角色适配器处理图层、锚点和局部形变。把官方节奏与角色自己的骨架分开。

走跑时，只有复制腿段角度会让长靴沿髋关节画弧、脚底乱飘。需要同时看：

- 左右步相反相，支撑脚落地、摆动脚抬起。
- 每帧计算旋转导致的脚底偏移，再用平移补偿到目标落点。
- 步幅、鞋转角、抬脚高度分开调；走路和跑步各有参数。
- 再检查身体前倾、手臂后摆、脚掌方向和停止后的回中立。

r06 仍是可见腿和靴子的刚性分件，不等于完整膝/踝骨架。目标落点跟随 kit，未承诺地面绝对无滑移。需要大幅屈膝或侧视跑姿时，应补侧面/弯腿差分或连续网格，不能无限增大旋转角。

跳跃保留预备压缩、腾空伸展、空中收腿、着地回弹。用户接受的待机幅度和跳跃幅度分别保存，修走路不能覆盖这两组参数。

## 附属动态的使用范围

r05 引入现有纹理上的小范围位移场，用受限弹簧驱动发梢、翼尖和尾部。连接点和五官区域权重为零；不需要重生整张图，也不需要拆穿遮挡关系。它只适合微动，不是完整独立翅膀/尾巴模型；坐姿暂禁用。大幅拍翼、甩尾需要真正拆层及遮挡补全。

预览提供开关做对照。先看轮廓和接缝，再看运动是否存在，最后看幅度是否合适；不能只凭弹簧数值变化就认定画面自然。

## 最少但有用的检查

| 修改 | 必须检查 | 不必重复 |
| --- | --- | --- |
| 步幅、抬脚 | 固定路线完整走跑周期，脚底落点和停止恢复 | 母版生成、眼区配准 |
| 招手掌心 | 抬手、最大摆幅、落手、恢复中立 | 全部表情生成 |
| 眼区 | 原尺寸/桌宠尺寸、半闭、闭眼、眼区外零改动 | 原位双腿拆件 |
| 附属弹簧 | 开关对照、起停、跳跃、轮廓与性能 | 官方全库重采样 |
| 打包 | manifest/资产路径、许可、ZIP、实际宿主加载 | 重新绘图 |

预览按 60fps 固定时间步导出，PNG 可逐张检查，接触表便于发现趋势，timeline 保存状态与参数。抽样帧不要冒充逐帧完整通过。官方参考库只采一次；仓库保存可复现脚本和版本依据，不分发官方受限制贴图。

随机走路可能不到一秒就结束；用于步态验收时指定固定起点/终点和足够长的舞台。记录是否真正覆盖多个完整周期。

## 常见失败与停止返工条件

| 失败 | 原因 | 下一步 |
| --- | --- | --- |
| 脸/身体扭曲 | 跨角色锚点、独立缩放、旧 atlas 混用 | 回锁定母版原位重组，再局部绑定 |
| 招手掌心反向 | 只有手臂旋转，没有掌心差分 | 新建动作专用手臂，结束恢复 |
| 走跑像甩腿 | 只映射角度，没约束脚底 | 分离步幅/角度/抬脚并补偿旋转位移 |
| 手臂被头发吞掉 | 所有动作共用固定层序 | 抬手时切到侧发前，落手回原层序 |
| 原位正常、动作露洞 | 没补遮挡区或接缝覆盖不足 | 仅补露洞区域，并检查极值帧 |
| 图像反复重生却没改善 | 问题其实来自几何/遮罩/层序 | 先定位参数和像素来源，不再整图重跑 |

同一个问题连续两次无改善，换方法；保留失败原因和证据。一个参数修复就能解决的问题，不引入另一整套模型运行环境。

## 如何迁移为你自己的角色

复制目录结构和验证方式，不复制本角色坐标。先只做待机、眨眼和一个手臂动作，确认原位与遮挡，再加腿和坐姿。名字、模型路径、包 ID、脚底和各锚点都要独立定义。先读 `docs/SOURCES.md` 的官方 API/许可，再决定是否引入第三方自动分层或 Live2D 工具。

经验记录至少包含：输入版本、要解决的问题、工具与提示词、编辑范围、参数差异、验证证据、失败及后续边界。`jobs.csv` 记简表，对应版本 README 记细节。这样别人能判断哪些是做过并检查的，哪些仍只是方案。

## 实际宿主补出的失败案例

r06 第一次 ZIP 导入被拒绝：`vocab.neutral.seconds 应为正数`。浏览器自建预览未校验该字段；修复为各词提供正数 seconds 后，本机导入成功。构建检查现已覆盖此条件。r04/r05 是历史开发阶段包，不能拿其旧 manifest 当发布模板；以 r06 为准。

## 跑步遮挡修正（r06 0.6.1）

跑步后摆手臂应进入身体和遮挡补画层后方；招手抬手则需要在侧发前。r06 初版只考虑招手的层序，导致跑步时远侧手穿到裙子前面。修正后按动作设置 behind-body / normal / wave 三种层序，停跑短暂平滑退出，再恢复普通手臂。用一次连续跑步→停步→招手→回中立导出验证，不能只分别启动三个动作而漏掉状态残留。

### 0.6.2：修正过度遮挡的漏检

0.6.1 将双臂放到所有身体纹理后方，但身体纹理还包含翅膀、尾巴，头层还包含长发，结果把近侧手也吞掉。接触表虽然检查过，却只确认了不穿到裙子前面，没有检查手掌仍然可见，该版视觉判定错误。

现在区分近远臂：远臂留在后层；近臂在侧发/翼前，用原画坐标的躯干衣裙遮挡路径隐藏重叠区域，保留向后伸出的袖口与手掌。同时独立配置两臂后摆角度。检查必须同时满足不穿身、近手可见、肩部连接、停跑与招手恢复，不能仅检查 DOM 层序名称。

### 0.6.3：遮罩必须固定在遮挡物坐标中

0.6.2 的躯干遮罩挂在旋转手臂节点上，SVG userSpaceOnUse 仍属于该节点的局部坐标，遮罩随臂转动导致异常裁切。修复为未变换的外层 arm slot 挂遮罩，内层 arm node 独立旋转；层序移动外层，素材和角度只改内层。验证不仅检查手可见，还需检查肩袖连续、遮挡边界固定以及退出动作后移除遮罩。

### 0.6.4：关节连接区不得当作穿身区域裁掉

0.6.3 固定了遮罩坐标，但躯干轮廓仍覆盖近侧肩点，肩部肤色连接被切除。新增可编辑 run_shoulder_keep 椭圆，在固定躯干遮罩内显式保留肩部关节。不要把接触表上手可见等同于肩袖连续；需放大对比关节区域。

### 0.6.5：头脸与长发不能共用一个前景层

用户发现普通走路时发尾遮住手。原 head 贴图含脸、刘海与长发，整层放在手臂前方会使发尾吞手。现用互补原位 SVG 裁剪分成上半头部与下半长发显示层，不重生成、不缩放贴图。顺序为身体→发尾→普通手臂→上半头部；跑步近远臂与招手仍分别处理。分界和发根形变过渡保存在 secondary-config.json，根部位移归零避免裁剪接缝。


### 0.6.6：静止也必须保留正确层序

0.6.5 把发尾放到独立手臂之后，却保留了“手臂角度接近零就切回整身贴图”的优化。这样停下来时，整身中的手又回到头发后面。0.6.6 站姿始终保留独立手臂与无臂身体；坐姿仍用专用差分。不要让性能分支改变角色的遮挡语义。

新增 `rig-v005-r06/behavior-config.json` 控制拖拽腿摆、思考、工作、倾听的小幅头手姿态。它们复用原画眼睑，不等于已制作独立嘴型或完整表情。修改后运行 `scripts/sync-r06-config.py`，不需要重新出图。待机 0.7、跳跃 0.65 维持原设定。

预览里的“检查左右交互与状态”用公开 kit 接口按固定帧触发，检查四条链路 × 左右朝向：待机→招手→恢复、跑→停→招手、拖拽→释放→落地、思考→工作→倾听→平静。指针带显式时间，拖拽起点取真实命中圆，不硬写角色屏幕位置。导出 96 张采样帧，附动作返回值、层序、掌心差分状态。检查方法：

```powershell
.venv/Scripts/python.exe scripts/inspect-r02-qa.py <下载的JSON路径> ../rig-v005-r06/qa-interactions-v066
```

本轮回看了八张接触表和六张放大关节裁图，见该目录的 `report.json` 与 `joint-details.png`。记录显示掌心差分、层序和拖拽按压均正确恢复；这不代表所有 60 fps 中间帧都已检查。新版已通过真实导入；沙箱验收记录与桌面窗口输入、重启测试分开记录。

宿主验证器也必须防止假通过：后台标签页会节流 requestAnimationFrame，等待两秒曾只收到两帧。现改为每词 120 次固定 1/60 秒 tick，每次等待 figure-frame 回执后再推进；18 个词均收到回执且无宿主错误，跳跃记录了 crouch→air→land→idle。完整报告为 `installed-sandbox-v066.json`。这是运行协议检查，不能替代视觉与桌面窗口验收。


### 把宿主输入、重载和素材版本分开验证

`python scripts/verify-installed.py` 从本机 7797 端口读取已安装包全部文件，与工作区逐字节比较 SHA-256。0.6.6 的 27 项一致。只看预览标题或 manifest 版本不够，代码和贴图都可能混用旧文件。

`preview/installed-r06.html` 的“检查宿主交互与重新加载”通过真实 figure-frame 的公开消息协议测试 13 项：左右朝向的空白点击、拖拽松手、pointer cancel、drop、睡眠点击唤醒、倾听中断跑步，以及全新 iframe 重载。释放后必须经历 air/land、最后 idle 且 pressing=false；重载后核对词表与待机。报告 `installed-interactions-v066.json` 全部通过。

这里的 drop 检查只是跨窗口放下所用的协议，不代表真实多显示器窗口路由已经通过；iframe 重载也不能写成 Coopanion 进程重启通过。明确区分才能让后来的人复现实测结果。
